# 架构与实时切换

`scores.py` 校验独立谱文件并构造不可变事件；`library.py` 解析明确的旋律／伴奏标记。`Playback` 调度整条完整曲谱，`Controller` 管理传输状态，`WindowsKeyboard` 用扫描码发送输入。

```text
网页命令 → 有界命令队列 → Engine 输入线程 → Controller → Playback → WindowsKeyboard
                              ↑                              ↓
           F5–F10 / Insert / Delete / PageUp / PageDown 消息队列       完整事件索引
```

RegisterHotKey、PeekMessageW 和 SendInput 在同一输入线程运行。HTTP 工作线程只发送控制命令和读取快照。退出、停止优先处理，不会因为同一轮收到声部快捷键而重新开始。

## 声部切换的边界

`Controller.switch_part` 只更新自动声部，不重建播放器。`Playback.event_filter(index, event)` 在每组按键即将发送时，从对应完整事件中选择琴键。空声部事件仍消费时间轴索引，但不发送空按键。

- 在事件消费前切换：这一组使用新声部。
- 在事件消费后切换：不重新触发这一组，即使部分琴键刚刚被静音。
- 当前持有的按键：保持原释放时间，不制造第二次按下。
- 休止、变速后的原曲坐标、循环 A/B 边界及次数：全部保留。
- 停止、暂停、焦点丢失与明显调度延迟：保持已有行为。

这避免了替换过滤后曲谱时重新查找索引导致的边界重音、漏组与时钟漂移。

网页试听有短时间的 Web Audio 提前调度。声部切换只取消尚未开始的音源，并解除这些事件的去重标记，使用新声部重新排入原时刻；已开始的音符尾音保留。试听通知受本机 HTTP 轮询延迟影响；游戏中的 F5–F7 由输入线程直接处理。

跳段与进度跳转保留 `playing` 状态，更新播放原点和事件索引，并立即在目标位置继续；切歌在验证新谱后原子替换播放器，保持当前演奏状态。倒计时期间跳转或切歌保留原截止时间。后台模式锁定游戏窗口句柄和进程 ID，前台用 `SendInput`，失焦时用 `PostMessageW` 发往游戏窗口；窗口关闭或进程变化即停止。Windows 消息投递成功只能证明消息进入队列，不能证明游戏处理了输入。

## 文件和安装

Python 包包含网页与公开练习谱；个人曲库位于包外。源码检出默认使用根目录 `songs/`，安装包默认使用用户主目录 `.lyre-studio/songs`，也可用 `--songs` 或环境变量覆盖。

`run.py` 只负责定位 src 包；后台进程仍调用同一套模块。开发工具和私有素材不是运行依赖。
